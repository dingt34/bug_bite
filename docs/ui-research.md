# 虫咬识途 UI 对标调研与优化建议

> 调研日期：2026-08-28  
> 范围：微信小程序通用体验、健康急救流程、拍照识别、户外安全与离线信息。  
> 方法：只采用微信官方设计资源、产品官网、官方帮助中心和官方应用商店页面。下文把“来源明确陈述的事实”和“针对本项目的设计推论”分开表达。

## 1. 结论摘要

“虫咬识途”不应被设计成以虫种百科为中心的工具，而应是一个**先处理风险、再辅助识别、最后保存记录**的安全助手。结合现有问卷结果与一手产品模式，推荐将全局体验调整为：

1. 首页首屏只突出一个应急主入口：**“我被咬/蜇了，立即判断”**；拍照识别作为并列但次一级入口，行前准备和图鉴下沉。
2. 安全处置流程保持“危险信号 → 接触类型/症状 → 行动建议”，每页只有一个主要任务和一个主要按钮。
3. 行动建议用“现在做什么 → 观察什么 → 何时求助”的编号卡片；紧急状态把拨打 120 固定为最高优先级。
4. 图片识别页采用“拍照/相册入口 → 拍摄引导 → 局部识别状态 → 多候选结果 → 去安全判断”，避免把 AI 候选包装成确诊。
5. 离线内容应成为可见能力：明确显示“已离线可用 / 待更新 / 下载中”，并在首页或个人中心提供统一入口。
6. 视觉上继续使用清新绿与浅湖蓝，但医疗危险只用红/橙强调；卡通图标应统一成同一套线性或扁平插画，避免混用不同风格 Emoji。

## 2. 一手来源观察

### 2.1 微信官方：轻量、聚焦、一致、反馈明确

微信小程序设计指南强调尊重用户知情权和操作权，减少与当前目标无关的干扰，让页面重点和流程清楚；对等待过程与操作结果都应提供反馈。官方 WeUI 则提供与微信原生体验一致的 `button`、`cell`、`dialog`、`progress`、`toast`、`actionsheet`、`icon` 等基础模式。

来源：

- [微信小程序设计指南（官方）](https://developers.weixin.qq.com/miniprogram/design/)
- [腾讯 WeUI for 小程序](https://github.com/Tencent/weui-wxss)
- [微信小程序 WeUI 组件库](https://github.com/wechat-miniprogram/weui-miniprogram)

对本项目的推论：

- 首页不宜让四个功能卡片拥有完全相同的视觉权重，应区分“立即处置”与“出行前准备”。
- 点赞、收藏、加载建议等局部操作应只在按钮或卡片内部显示状态，不能让整个社群页面进入遮罩式加载。
- 提交、保存、复制、下载完成后，应显示短暂且明确的成功反馈；失败时在原位置给出原因和重试入口。
- 顶部导航、返回箭头、标题、按钮和表单控件应复用同一套公共组件和样式变量。

### 2.2 American Red Cross：急救内容按优先级分步呈现

美国红十字会官方 First Aid 产品以“简单、逐步”的急救说明为核心；紧急场景会优先给出操作步骤和呼叫急救按钮。官方还强调内容预加载，使安全信息可以随时访问，并用视频、动画补充学习内容。

来源：

- [American Red Cross 官方移动应用页](https://www.redcross.org/get-help/how-to-prepare-for-emergencies/mobile-apps.html)
- [Red Cross First Aid App 功能说明](https://www.redcross.org/about-us/news-and-events/news/Red-Cross-First-Aid-App-Can-Help-Save-Lives.html)
- [Red Cross 官方 First Aid Steps](https://www.redcross.org/take-a-class/first-aid/performing-first-aid/first-aid-steps)

对本项目的推论：

- 当前“现在做什么 / 观察什么 / 何时求助”结构方向正确，应继续强化顺序，而不是把所有建议做成同权重文字块。
- 紧急结果页应先出现“拨打 120”和第一步行动，来源、免责声明、事件摘要放在后面，避免抢占急救注意力。
- 可加入 1～3 张关键操作示意图，但文字步骤必须独立可用，不能让视频成为获取建议的前置条件。
- 普通状态用绿/蓝，升级观察用橙，紧急状态用红；颜色必须同时配合文字、图标和标题，不能只依赖颜色表达风险。

### 2.3 Seek by iNaturalist：相机直达、实时反馈、展示识别层级

Seek 官方指南允许用户从任意页面快速进入相机；相机界面会持续给出识别反馈，并用分类层级进度表示当前识别能具体到界、门、纲、目、科、属或种。官方产品还提供相机与相册两种来源，并在进入相机时提醒用户注意环境安全。Seek 默认不要求注册，精确位置会被模糊处理。

来源：

- [Seek by iNaturalist 官方产品页](https://www.inaturalist.org/pages/seek_app)
- [Seek 官方用户指南（PDF）](https://static.inaturalist.org/wiki_page_attachments/SeekUserGuide2020.pdf)
- [Seek 官方隐私政策](https://www.inaturalist.org/pages/seek_privacy_policy)
- [Seek by iNaturalist 官方 App Store 页面](https://apps.apple.com/us/app/seek-by-inaturalist/id1353224144)

对本项目的推论：

- 首页可放一个直接拍照的快捷动作，但危险筛查入口的视觉优先级仍应更高。
- 拍摄框内应显示简短引导，例如“让虫体占画面约 1/3”“保持清晰”“可补拍背部/侧面”，并提供相册切换。
- 识别过程用图片卡片内部的扫描动画或进度提示，不使用全页加载。
- 结果应显示“可能是”及 2～3 个候选，明确候选层级和不确定性；主按钮应是“有症状，去安全判断”。
- 上传图片与位置信息前应就地说明用途；地区推荐不需要精确展示用户坐标。

### 2.4 iNaturalist：AI 建议与社区确认分层

iNaturalist 官方说明，应用可以先给出自动识别建议，再由自然观察者社区确认或修正；观察记录围绕照片、时间、地点和讨论展开。它与 Seek 的差异也说明了“私人即时识别”和“公开社区协作”是两种不同任务。

来源：

- [iNaturalist 官方首页](https://www.inaturalist.org/)
- [iNaturalist 与 Seek 的官方对比说明](https://help.inaturalist.org/en/support/solutions/articles/151000169914-what-is-the-difference-between-inaturalist-and-seek-by-inaturalist-)
- [iNaturalist 官方 Google Play 页面](https://play.google.com/store/apps/details?id=org.inaturalist.android)

对本项目的推论：

- AI 识别结果和社群意见必须使用不同标签，例如“AI 候选”和“社群补充”，不能合并成一个确定结论。
- 经历分享卡片应以图片和简短结论为主，时间、地区、接触方式、当前状态为次级元数据。
- “我也有类似经历”适合作为复制事件信息的入口，但进入后应标明“已从原帖带入，可修改”，并提供返回原帖。

### 2.5 AllTrails：离线能力必须有明确状态和固定入口

AllTrails 官方帮助中心把离线地图下载放在路线卡片上，下载完成后图标发生明确变化；已下载内容集中在“Saved > Downloads”，离线时仍能访问。路线导航中，计划路线与实际轨迹使用不同颜色。

来源：

- [AllTrails 官方：下载离线地图](https://support.alltrails.com/hc/en-us/articles/37213318235028-How-to-download-maps-to-your-phone-for-offline-use)
- [AllTrails 官方：使用已下载地图导航](https://support.alltrails.com/hc/en-gb/articles/37213942810132-How-to-use-your-downloaded-maps-for-navigation)
- [AllTrails 官方 Google Play 页面](https://play.google.com/store/apps/details?id=com.alltrails.alltrails)

对本项目的推论：

- “离线急救卡”不能只在说明文字里出现，应有可观察状态：未下载、下载中、已离线可用、内容有更新。
- 建议在首页安全提示下增加轻量状态条：“急救卡已离线可用 · 更新于 XX-XX”，点击进入离线卡管理。
- 路线页应把起点、途经点、终点用稳定的颜色和图形编码区分；选中路线与备选路线保持明显差异。
- 无网络时保留已保存路线、风险提示和行动卡，同时明确哪些在线能力不可用。

## 3. 针对现有页面的优化方案

### 3.1 首页

现状是“行前准备、虫咬处置、图鉴、AI 助手”四张相近卡片。建议改成三层：

1. **应急主卡**：标题“我被咬/蜇了”，副文案“先判断危险信号，再获得处理步骤”，使用全宽绿色主按钮“立即判断”。
2. **识别次卡**：拍照图标 + “拍虫体辅助识别”，使用白底描边卡；明确“不能代替安全判断”。
3. **准备与学习**：行前准备、常见虫种、AI 助手改为两列或紧凑列表，不与应急入口争夺注意力。

非诊断提示保留，但从大面积警告框改成短说明；紧急拨打 120 保持红色文字。首屏避免同时出现过多标签。

### 3.2 危险信号页

- 顶部增加“第 1 步 / 共 4 步”，标题保持动作导向。
- 危险信号按统一卡片高度排列：卡通图标、名称、最多两行说明、右侧选中状态。
- 选中任一项后，底部操作区立即切换为红色“立即求助”，并在同一区域显示拨打 120；不要额外弹窗打断。
- 未选中时主按钮文案保持“没有以上信号，继续”，降低理解成本。

### 3.3 接触类型、症状选择与复查

- 双列选项保持等高，图标固定在同一基线，文字超过两行时缩短描述而不是无限增高。
- 单选使用圆点或单选标识，多选使用方形勾选标识，避免仅靠背景色区分。
- 必填问题优先展示，选填内容折叠为“补充信息”，减少滚动长度。
- 已通过“我也有类似经历”带入的值顶部显示来源条：“来自某条经历，可修改”。

### 3.4 行动建议页

建议固定信息顺序：

1. 风险等级 + 一句话结论；
2. 现在做什么；
3. 观察什么；
4. 何时求助；
5. 保存/复制事件摘要；
6. 判断依据与免责声明。

普通页面只保留一个底部主操作“保存事件记录”，返回首页作为文字按钮。紧急页面则将“拨打 120”固定在底部，其他操作降级。

### 3.5 图片识别页

- 上传前：大面积取景框，中央统一相机插画，底部并列“拍照”“从相册选择”。
- 上传后：显示原图、重拍入口和清晰度检查提示。
- 识别中：只覆盖图片区域，显示“正在查找相似虫种”；保留返回能力。
- 识别后：2～3 个候选卡片，包含缩略图、名称、候选层级、相似程度和“为什么不确定”。
- 页面底部固定主按钮“有症状，去安全判断”；“查看图鉴对比”作为次按钮。

### 3.6 行前准备与路线

- 必填的地区、月份、活动类型放在第一组；路线、生境、住宿、同行人群和装备作为渐进补充。
- 顶部进度只计算必填项，完成后直接出现“生成建议”。
- 路线输入区继续使用垂直路径结构，但起点、途经点、终点使用不同图形而非仅不同颜色。
- 地区筛选结果应显示在标题旁，例如“杭州 · 12 条”，空状态说明当前筛选条件并提供“一键清除”。
- 每张路线卡片显示离线状态；下载完成后图标和文案都变化，并集中到“我的路线/离线内容”。

### 3.7 社群

- 经历卡首屏信息控制为：头像与昵称、地区/时间、1～3 张图片、两行摘要、风险标签、互动区。
- 路线只作为经历分享中的可选附件，采用紧凑路线小卡，不做独立内容栏目。
- 点赞、收藏使用按钮内局部反馈；操作失败时恢复原状态并显示轻提示。
- AI 候选、用户自述和社区意见使用不同视觉标签，避免形成医学诊断暗示。

## 4. 推荐视觉规范

### 4.1 颜色角色

| 角色 | 建议颜色 | 用途 |
| --- | --- | --- |
| 主色 | `#2E8B63` | 主按钮、选中态、进度 |
| 浅主色 | `#EAF7F1` | 卡片底色、标签背景 |
| 辅助蓝 | `#EAF5FB` / `#3F8FB5` | 路线、信息提示、识别状态 |
| 警示橙 | `#F59E42` | 需要关注或升级观察 |
| 紧急红 | `#D94A4A` | 危险信号、拨打 120 |
| 主文字 | `#20342B` | 标题与正文 |
| 次文字 | `#68776F` | 说明与元数据 |
| 分隔线 | `#DDE9E3` | 卡片和列表边界 |

所有风险表达都应同时包含图标和文字。绿色不用于紧急确认，红色也不用于普通装饰。

### 4.2 字体与层级

- 页面标题：17px，半粗体，统一由顶部导航组件控制。
- 卡片主标题：16～18px，最多两级。
- 正文：14～16px，急救步骤适当增大行高。
- 次级信息：12～14px，但隐私、风险和免责声明不能使用过浅颜色。
- 数字步骤采用紧凑圆形或小标签，不使用大面积装饰数字。

### 4.3 卡通图标

- 选择一套圆角、低细节、自然主题的扁平图标；统一线宽、色板和视角。
- 建议覆盖：盾牌、相机、虫体、皮肤症状、急救包、地图、背包、医院、电话、离线下载。
- 图标只帮助扫描，不替代文字；危险图标保持严肃，避免使用过于可爱的表情弱化风险。
- 页面内不混用彩色 Emoji、线性 SVG 和写实图片作为同级功能图标。

## 5. 交互状态清单

每个可操作页面至少覆盖以下状态：

- 初始态：告诉用户下一步做什么；
- 进行中：局部加载、按钮禁用并保留返回；
- 成功态：结果明确、主下一步突出；
- 空状态：解释为什么没有内容，并给出恢复入口；
- 失败态：保留已填写内容，显示原因和重试；
- 离线态：指出仍可使用的内容和受限功能；
- 紧急态：中断普通流程，优先呈现呼救与立即行动。

特别检查：点赞、收藏、图片识别、路线规划、生成行前建议、保存记录、离线下载，不应使用无差别的全页加载遮罩。

## 6. 建议实施顺序

### P0：直接影响安全与主流程

1. 重排首页入口优先级。
2. 统一危险筛查与行动建议的信息顺序。
3. 完善识别页的局部状态和不确定性表达。
4. 修正全页加载为局部反馈。

### P1：提升完成率与问卷需求匹配

1. 行前准备必填/选填分组与渐进展开。
2. 事件记录、就医摘要和复查入口统一。
3. 离线急救卡增加可见状态与管理入口。

### P2：精致度与一致性

1. 替换混用 Emoji，建立统一卡通图标集。
2. 统一颜色、圆角、间距和空状态插画。
3. 社群、路线附件和筛选结果的卡片规范化。

## 7. 验收建议

- 用户进入首页 3 秒内能指出“被咬后从哪里开始”。
- 从首页到获得行动建议，主路径中每页只有一个明显主按钮。
- 用户不阅读说明文字，也能区分普通、观察、紧急三种风险状态。
- 相机、识别、点赞、收藏和路线加载时，页面其他区域仍可正常阅读或返回。
- 断网后仍能打开核心急救步骤、已保存事件和已下载路线，并看见明确离线标识。
- 在窄屏、系统大字体和深色模式下检查标题截断、按钮换行与选项对齐。
