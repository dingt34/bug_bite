# “疑似蜱附着”单一对象全流程设计

## 目标

用一个范围可控、科学边界清楚的对象跑通小程序完整闭环：发现疑似附着虫体后，用户能先排除紧急情况，获得不延误的移除提示，记录关键事实，得到基于症状的分级建议，并在之后复查。

这里使用“疑似蜱附着”而非“蜱虫识别”。蜱属于蛛形纲，不是真正的昆虫；产品沿用大众熟悉的“虫咬”入口，但在关键页面纠正分类。

## 核心原则

1. **先救急**：危险信号永远在图片和普通问答之前。
2. **先移除**：虫体仍附着时，不为拍照、识别或等待就医而延迟安全移除。
3. **图片降权**：图片只返回“疑似类别”，不判断物种、病原体、患病概率，也不进入风险分级。
4. **症状驱动**：分级只使用危险信号、症状、敏感部位、趋势、活动影响、附着状态与时长。
5. **不做处方**：不自动推荐抗生素、检查项目或疾病结论；这些决策交给医疗专业人员。
6. **可追溯**：保存发生时间、地点、附着时长、移除状态、照片、症状、处理和规则版本。

## 用户流程

### 主流程

首页“疑似蜱附着：从处置到复查” → 危险信号筛查 → 已标记“疑似蜱等虫体附着”的接触类型 → 症状与附着状态记录 → 规则分级 → 行动建议 → 保存事件 → 定期复查。

### 图片辅助支线

首页“拍附着虫体辅助识别” → 拍照/相册 → 本地演示候选 → 明确不确定性 → “进入蜱附着安全流程” → 回到同一危险信号筛查入口。

图片支线不是主流程的前置条件。用户不拍照也能完成整个安全闭环。

### 紧急支线

任一危险信号 → 立即求助结果页 → 拨打 120 / 急诊提示 → 保存紧急事件摘要。紧急事件不能通过普通自评自动降级。

## 页面状态与关键信息

| 页面 | 用户任务 | 必须呈现 | 不能呈现 |
| --- | --- | --- | --- |
| 首页 | 找到正确入口 | 单一流程入口、紧急提示、图片辅助入口 | “AI 确诊蜱虫” |
| 危险筛查 | 判断是否立即求助 | 呼吸、口咽肿胀、意识、快速加重等信号 | 用图片结果替代身体风险 |
| 接触类型 | 确认流程上下文 | 默认标记疑似附着类型，但允许更改 | 锁死选择或暗示确诊 |
| 症状记录 | 保存关键事实 | 时间、地点、部位、症状、趋势、附着时长、移除状态 | 强制先拍照、疾病问卷 |
| 行动建议 | 立即知道下一步 | 正确移除、禁忌做法、观察点、求助条件 | 自动用药、病原体结论 |
| 事件记录 | 带走完整摘要 | 输入事实、分级依据、规则版本、图片 | 只保存一个“风险分数” |
| 复查 | 发现变化 | 当前症状、趋势、虫体状态、危险信号 | 自动把既往紧急事件降级 |

## 分级边界

- **紧急求助**：命中危险信号，立即中断普通问答。
- **尽快咨询**：出现全身不适、敏感部位、症状加重、明显活动受限、未完整移除或报告较长附着等需专业评估的情况。
- **观察记录**：暂未发现上述条件；完成安全移除与清洁，按提示观察变化。

分级是行动优先级，不是疾病严重程度或诊断结论。

## 验收标准

- 首页可一键进入疑似蜱附着流程，且上下文不会在页面跳转中丢失。
- 图片页主候选为“疑似蜱类”，明确它是固定演示且不能判断病原体。
- 仍附着时，页面明确提示不要为了拍照或识别延迟移除。
- 结果页包含细尖镊子、贴近皮肤、持续均匀上拉、禁止扭转/猛拽/油脂/加热/指甲油、清洁和全身检查。
- 不能轻松取出的口器残留不会引导用户继续强挖。
- 数天至数周出现发热、皮疹或新发全身不适时提示就医，并携带时间和地点信息。
- 图片候选不参与风险规则；事件能保存并进入复查。
- 自动化测试覆盖入口路由、上下文保留、候选文案、核心处置文案和风险规则。

## 10. 详细交互稿

### 10.1 首页入口

从上到下展示品牌与覆盖地区、主行动卡“我被咬/蜇了，立即判断”、单一对象卡“疑似蜱附着全流程”、图片辅助入口和固定急救条。单一对象卡的副文案为“先排危险，再处理、记录、复查”。

主行动卡和单一对象卡使用视觉主次关系；识别入口必须标注“辅助”，不能成为安全判断的前置条件。

### 10.2 危险信号筛查

每项信号使用可点击卡片，包含图标、短标题、生活化解释和勾选状态。蜱流程额外显示进行性肢体无力/麻痹、抽搐或意识混乱、协调障碍和严重异常出血。

- 未选择信号：按钮为“没有以上信号，继续记录”；
- 选择任一信号：立即出现红色急救条，按钮变为“立即求助·中断问答”；
- 紧急结果可保存摘要，但不能通过普通自评自动降级。

### 10.3 接触类型确认

默认高亮“疑似蜱等虫体附着”，说明“蜱属于蛛形纲，当前只做安全处置分流”。用户可以改选其他类型；改选后，问题、建议和复查字段随类型切换。

### 10.4 症状与事实记录

采用“进度条 + 分组卡片”，顺序为：发生时间 → 可能接触地点 → 身体部位 → 局部症状 → 全身症状 → 变化趋势 → 活动影响 → 估计附着时间 → 移除状态 → 已采取措施 → 证据图片。

| 字段 | 作用 | 必填 |
| --- | --- | --- |
| 发生时间 | 判断暴露时点 | 是 |
| 可能接触地点 | 供专业人员结合地区判断 | 是 |
| 身体部位/局部症状 | 描述当前局部表现 | 是 |
| 全身症状/变化趋势 | 发现需升级的变化 | 是 |
| 附着时间/移除状态 | 决定是否需要专业评估 | 是 |
| 已采取措施 | 记录事实，不生成处方 | 否 |
| 虫体/伤口照片 | 就医沟通与事件留档 | 否 |

页面顶部固定提示：“虫体仍附着时先处理，不要为了拍照或识别延迟移除”。图片失败不阻塞提交，也不能清空已填写内容。

### 10.5 行动建议结果

结果页固定四段：

1. **现在做什么**：细尖镊子贴近皮肤、稳定向上拉、清洁、检查其他部位；
2. **不要做什么**：不扭转、不猛拽、不挤压、不用油脂/加热/指甲油、不反复挑挖；
3. **观察什么**：移除状态、局部范围、体温和新发全身症状；
4. **何时求助**：危险信号立即急救；数天至数周出现发热、皮疹、头痛、乏力、肌痛或胃肠道症状时尽快就医。

观察级结果显示“前 14 天建议每日快速复查；随后数周仍需留意变化”。咨询级把“尽快联系医疗机构”置于首项；紧急级只保留急救行动。

### 10.6 事件摘要与复查

保存后生成可复制摘要：接触类型、发生时间、可能地点、部位、附着时间、移除状态、症状、风险分级、触发依据、已采取措施和图片状态。

复查入口位于事件详情页，不要求每天上传照片。复查先问危险信号，再问局部/全身表现、趋势、活动影响和移除状态；只能升级，不能把紧急事件自动降级。

## 11. 状态机

```text
未开始 → 危险筛查
  ├─命中危险信号 → 紧急求助结果 → 保存紧急事件
  └─无危险信号 → 接触类型确认
       ├─改选其他类型 → 对应类型问题
       └─确认疑似蜱 → 症状/事实记录
            ├─缺少必填 → 定位缺失字段
            └─完成 → 规则分级结果
                 ├─观察 → 保存事件 → 14天复查
                 ├─咨询 → 保存事件 → 尽快就医
                 └─紧急 → 保存事件 → 120/急诊
```

## 12. 边界与失败场景

| 场景 | 处理 |
| --- | --- |
| 不确定是否为蜱 | 保持“疑似”措辞，仍可按附着流程处理 |
| 没有镊子或位置特殊 | 不挤压；无法安全操作时尽快请医护人员协助 |
| 口器疑似残留 | 不引导针挑或反复挖；不能轻松取出则咨询专业人员 |
| 图片模糊/无图片 | 显示“无法判断”，继续症状分流 |
| 网络中断 | 已缓存处置卡可用，本地事件稍后同步 |
| 儿童、孕妇、免疫低下者 | 提醒可更早咨询，不自动给药或改变诊断 |

## 13. 真实识别接入约束

识别服务只返回候选类别、质量状态、模型版本和免责声明。客户端不得用置信度改变 `riskLevel`，不得把候选写入“诊断”字段，不得在缺少症状和暴露信息时生成疾病名称。上线前须经过隐私、安全和临床专业评审。
