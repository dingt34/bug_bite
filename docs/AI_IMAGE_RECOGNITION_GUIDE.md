# AI 助手图片分析说明

## 当前实现

- 提供商：阿里云百炼千问多模态，默认模型 `qwen3.7-flash`。
- 云函数：继续使用历史名称 `cozeAgent`，仅为避免重新创建和切换云函数。
- 图片数量：每次最多 2 张，支持“虫体图片”和“伤口图片”标签，顺序会传给模型。
- 传输链路：小程序临时上传→微信云文件 ID→云函数换取限时 HTTPS 地址→百炼 OpenAI 兼容接口。
- 知识链路：文字安全事实提取→图片候选预处理→检索最多 3 个结构化知识包→本地规则分级→千问基于检索内容整理回答。
- 清理：无论请求成功或失败，小程序都会尝试删除临时云文件；页面卸载时也会再次尝试。

## 安全与隐私边界

1. 只接受当前微信云环境产生的 `cloud://` 文件 ID，不接受客户端传入的外部 URL。
2. 发送图片前必须经用户弹窗确认，明确图片会交由微信云存储和阿里云百炼处理。
3. 图片只用于描述可见特征和建议候选类群，不作为虫种、疾病、病原体或严重程度确诊。
4. 图片候选和置信度不参与风险分级；危险信号始终优先，必要时直接建议呼叫 120。
5. 不记录 API Key、图片临时 URL 或完整个人记录。
6. 不自动推荐处方药、抗生素或具体剂量。

## 项目组知识库

组长提供的知识库含 45 个核心/候选条目和 21 个可复用安全规则。当前所有条目为 `DRAFT`，16 个候选条目的媒体状态为 `PENDING_LICENSE`。

完整结构化知识库随云函数部署在 `cloudfunctions/cozeAgent/knowledge-base`，包含对象资料、来源、内容块和行动规则。`knowledge-retrieval.js` 负责校验候选 ID、提取用户文字中明确出现的安全事实、检索最多 3 个知识包，并在代码层执行行动分级。

虫体图片的候选 ID 由千问预处理得到，但不会参与行动分级；只有用户文字中明确表达的危险信号和症状事实可以触发知识库规则。只有伤口图或无法识别虫体时不强行匹配对象知识包。

最终请求只携带命中的知识包，不会把全部 45 个条目塞进提示词。知识库仍为草稿，正式发布前仍需要逐条来源核验、医学/疾控审核和媒体授权完成。

## 环境变量

`cozeAgent` 需要：

- `DASHSCOPE_API_KEY`
- `AI_MODEL=qwen3.7-flash`
- `DASHSCOPE_BASE_URL=https://<workspace-host>/compatible-mode/v1`

密钥只存在云函数环境变量中。百炼专属 Base URL 必须与 API Key 所属业务空间一致。

## 真机验收清单

1. 不选图片时，文字多轮对话正常。
2. 单张虫体图返回可见特征、不确定候选和补拍建议。
3. 单张伤口图不输出确定性虫种、疾病或病原体诊断。
4. 两张图片的顺序和标签不混淆。
5. 危险信号会覆盖图片分析，优先显示急症建议。
6. 超时或上游错误时页面显示安全兜底信息。
7. 成功、失败和退出页面后，云存储中不应长期留存 `ai-chat/` 临时图片。
8. 云函数日志不包含 API Key、临时 URL 或完整个人数据。
9. 返回结果中的 `knowledgeObjectIds` 只包含 0～3 个有效对象 ID，`actionLevels` 不因图片候选变化而升级或降级。
